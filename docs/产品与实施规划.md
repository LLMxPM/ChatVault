# ChatVault 产品与实施规划

版本：V1.2 · 日期：2026-09-11 · 状态：桌面端开发规划。

## 1. 产品定位

ChatVault（拾文）是一款桌面端聊天附件归档与检索工具，面向长期通过 PC 微信收发资料的用户，以及拥有 WebDAV 的个人与 NAS 用户。

通过授权目录采集微信附件，在本地完成索引和搜索，将文件与元数据归档到用户配置的 WebDAV。优先交付 Windows，随后适配 macOS。

| 组成 | 职责 |
| --- | --- |
| 桌面客户端 | 目录选择、附件发现、文件检索、归档任务、预览与取回 |
| 本地索引 | SQLite 保存文件、来源与同步状态，支持离线查询 |
| 本地文件 | 上传暂存和下载缓存，支持任务恢复与按需打开 |
| Storage | WebDAV 保存内容对象、元数据日志与快照 |
| 多设备同步 | 各桌面端通过 WebDAV 交换元数据并重建本地索引 |

## 2. 核心使用场景

核心闭环：授权目录 → 发现附件 → 本地索引 → 内容哈希去重 → WebDAV 归档 → 多设备恢复元数据 → 搜索 → 按需下载。

1. 用文件名、类型、日期和账号组合找到历史附件。
2. 手动扫描或系统定时任务发现新附件并归档，失败任务重启后继续执行。
3. 相同内容保存一个对象，保留各次来源记录与原文件名。
4. 更换电脑后先从 WebDAV 恢复元数据，再按需下载附件。
5. 在文件详情中查看归档状态、来源依据和校验结果。

文件时间同时保存取值与含义，例如修改时间、发现时间。会话信息按实际提取结果展示，缺失字段显示“未知”，支持后续人工标注。

| 能力 | Windows | macOS |

| 微信目录自动发现 | 自动探测与手动补充 | 单独验证目录布局 |
| 增量归档 | 手动扫描与系统定时任务 | 复用流程，适配文件系统行为 |
| 文件检索 | 文件名、类型、日期、账号组合查询 | 复用索引与查询核心 |

| WebDAV 同步 | 上传、下载、日志同步与恢复 | 复用同步核心 |
| 预览与打开 | 常用格式预览、调用系统关联程序 | 适配系统打开能力 |

采集以授权目录内实际可访问的附件为基础。文件发现率和会话识别率分别统计，目录适配结果形成版本化能力记录。

## 4. 技术选型

依赖具体版本在项目初始化时核验并锁定。

| 层次 | 方案 | 职责 |
| --- | --- | --- |
| 桌面壳 | Tauri 2 | 窗口、托盘、目录授权、系统打开文件 |
| 桌面界面 | Vue 3 + TypeScript + Vite | 文件列表、过滤、任务和配置 |
| 核心 | Rust workspace | 独立封装采集、哈希、索引和同步逻辑 |
| 数据库 | SQLite + FTS5 | 每设备维护本地索引，通过元数据事件同步 |
| 内容标识 | BLAKE3 | 完整内容哈希，算法名称纳入存储格式 |
| Storage | WebDAV over HTTPS | 对象与元数据传输、能力探测和兼容性测试 |
| 包管理 | pnpm、Cargo | 前端 pnpm workspace，Rust Cargo workspace |

如引入 Python 辅助工具，使用 uv 管理依赖和 venv 虚拟环境。源文件开头写中文功能说明，函数注释解释职责、输入输出和约束；按职责拆分复杂模块。

## 5. 界面与交互

- 导航三项：文件库、任务、设置。WebDAV 配置只在设置维护；采集范围与调度在任务页维护。
- 主题：浅色默认，可切换深色或跟随系统；设计 token 与基础 UI 组件统一维护。
- 首次使用：默认进入任务 → 配置采集范围并立即运行 →（可选）设置中配置 WebDAV → 定时流水线。本地索引阶段显示“待归档”。
- 文件库：显示文件名、类型、大小、来源可信度、时间及含义、归档状态；支持组合过滤、分页与来源标注（改名/收藏）；空态引导去任务。
- 文件详情：展示同一对象的各来源记录、哈希、原名、远端校验结果，提供下载和打开入口。
- 任务中枢：采集范围、调度、立即运行流水线（扫描→归档→自动同步）、上传队列（暂停/重试）与恢复；进入后队列自动轮询；完整校验通过后显示“已校验”。发布/拉取无手动入口。
- 设置：身份、WebDAV、缓存、外观主题、存储概览与关于。
- 恢复资料库：任务页连接已有 Vault → 恢复元数据 → 建立本地索引 → 查询和按需取回；需二次确认。

- `docs/wechat-layout/` 研究记录：OS／微信版本、脱敏目录样本、附件类型、可读性、时间语义、来源依据与识别结果。

## 7. 可靠性与性能验收

以下为目标值。固定 Windows 机器规格、SSD、内存、数据集和 WebDAV 网络条件后记录实测结果。

| 验收项 | 标准 |
| --- | --- |
| 样本发现 | 已标注、静止且可读的支持样本全部发现；失败文件有可定位原因 |
| 去重与幂等 | 同内容生成一个逻辑对象；重复扫描／重放保持来源记录数量稳定 |
| 搜索 | 10 万记录热索引组合查询 P95 ≤ 500 ms；中文单字、双字、长词分别测试 |
| 列表 | 分页与虚拟列表按需加载；记录 50 万／100 万记录的性能表现 |
| 增量发现 | 手动触发或系统定时任务扫描后入队；定时周期由用户配置 |
| 故障恢复 | 上传、对象发布、日志提交各节点中断后重启，最终恢复同一结果 |
| 换机恢复 | 拉取元数据后即可检索；按需下载文件并复算哈希一致 |
| 运行体验 | 托盘任务可暂停、重启后可恢复，缓存用量受配置上限控制 |
| 发布验证 | 干净环境完成安装与启动，当前结构的资料库可重新打开，结构变化后重新初始化开发数据 |

## 8. 实施重点

执行顺序：目录实测 → 数据模型和格式 V1 → CLI 扫描入库 → WebDAV 往返 → 桌面 UI → 同步恢复 → Windows 发布 → macOS 适配。

- 目录兼容：按版本维护 Adapter 和脱敏样本，未知布局使用通用文件扫描。
- 来源识别：记录置信度与证据，通过人工标注补充会话信息。
- 协议兼容：连接时探测最低能力，按服务实测结果处理重试、条件请求与内容校验。
- 大库处理：扫描、哈希和上传分队列，采用流式处理与受限并发，逐步展示发现结果。
- 增量发现：不依赖文件系统监听。以用户手动触发扫描为主，并由操作系统定时任务按配置周期拉起扫描与归档；重复扫描通过本机发现键保持幂等。
- 数据保留：首期采用软删除，保留对象与日志用于恢复；微信源文件和归档记录分别管理。

详细数据模型与同步流程见[架构与同步设计](架构与同步设计.md)。
