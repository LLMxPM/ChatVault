## 2. 建议的首期安装流程

建议首期采用 Windows x64 的 NSIS `.exe` 安装包，优先当前用户安装、简体中文界面。Tauri 支持 NSIS 和 MSI，安装模式、语言及 WebView2 分发方式可以通过配置指定，具体字段参考 [Windows 安装器文档](https://v2.tauri.app/distribute/windows-installer/) 和 [配置参考](https://v2.tauri.app/reference/config/)。

1. 用户启动安装器，查看产品名、版本、发布者及安装位置。
2. 检查 WebView2 运行环境。首期可采用联网补齐方式；若要求完全离线安装，则采用携带离线安装器的分发方案并接受包体积增加。失败时应明确说明原因和重试方法。
3. 安装桌面程序、同版本 CLI 和必要资源，创建开始菜单入口，提供桌面快捷方式选项。
4. 安装完成后由用户选择是否启动应用。
5. 首次启动初始化固定的用户数据目录，选择微信或普通文件夹来源，预览识别结果，再开始本地扫描。
6. 引导用户配置并测试 WebDAV；未配置时仍可使用本地索引，明确显示待归档状态。
7. 用户启用定时归档后才创建计划任务，验证其能调用安装目录中的 CLI，并使用相同数据库与当前用户凭据。

当前用户安装不代表所有依赖安装及计划任务操作都一定无需提权，必须通过普通用户实测确认。

## 3. 按优先级实施

### P0：安装后正确运行

- 固定用户数据目录，创建目录并处理不可写、磁盘空间不足和数据库初始化失败；不将数据写入安装目录或依赖启动工作目录。
- 梳理缓存、暂存和恢复输出路径，保证桌面程序与计划任务使用同一份用户配置和资料库。
- 将 CLI 纳入发行构建和安装包；明确实际安装路径与查找方式，保证桌面与 CLI 版本一致。
- 开启 NSIS 打包，补齐当前用户安装、语言、WebView2 策略和快捷方式配置。
- 统一发行版本；增加从仓库根目录可运行的发行构建入口，锁定依赖并明确产物位置。
- 核验发布程序所需原生依赖，尤其 SQLite 的链接结果；用户机器不应依赖开发机的 Rust、Node、pnpm 或编译工具目录。

### P1：完整的安装和使用体验

- 统一产品显示名、窗口标题、安装器标题、快捷方式名、Windows 已安装应用条目及发布者。
- 制作可维护的图标母版，导出包含 16、24、32、48、64、128、256 像素档位的 ICO，以及界面需要的 SVG/PNG；可按安装器版式补充横幅和侧图。
- 使用同一品牌图形覆盖 EXE、窗口、任务栏、开始菜单、桌面快捷方式和卸载入口；如加入托盘，单独验证小尺寸托盘图标。
- 检查 100%、150%、200% 缩放下的清晰度，以及浅色、深色背景的可辨识性；无需为尚未支持的平台先制作完整素材包。
- 增加首次启动引导、版本与数据目录信息、打开日志目录入口，以及初始化失败时的可操作提示。
- 明确单实例策略和关闭窗口行为；托盘后台任务列入现有 V1.0 规划，若首期采用直接退出，应准确说明系统计划任务仍可独立运行。
- 卸载时清理程序、快捷方式与本应用计划任务；默认保留本地资料库和待上传副本。若提供清理数据选项，需要明确说明范围并由用户主动选择。
- 凭据清理由应用明确管理，不影响其他应用；卸载和重装不得删除微信原始附件或 WebDAV 远端归档。
- 覆盖安装或卸载时处理正在运行的桌面程序与 CLI，避免替换过程中破坏归档任务；安装位置改变后更新计划任务路径。

遵循仓库开发阶段约束：数据结构发生变化时明确提示重新初始化或重建开发数据，不新增历史结构迁移、双格式读取或版本兼容分支。同结构的数据保留与重启恢复仍属于必要可靠性要求。

### P2：对外分发与维护

- 确定分发位置、更新说明、安装包命名、校验和和问题反馈入口。
- 对外发布前落实 Windows 代码签名及密钥管理方案，实测下载和首次运行体验；签名不等于保证没有系统信誉提示。
- 补齐项目许可证文件、随包第三方声明及使用说明，当前 Cargo 中仅声明了许可证标识。
- 建立可复现的 Windows 构建与发布流水线；先验证手动安装新包的流程，再按需求加入自动更新。
- MSI、ARM64、离线安装独立包及 macOS 分发在有明确需求后另行安排。

## 4. 安装验收清单

| 场景 | 验收要求 |
| --- | --- |
| 干净系统 | 在约定支持的 Windows 版本中安装并启动，无开发工具和本地库路径依赖 |
| 普通用户 | 安装、扫描、凭据保存、定时归档均可按设计完成，提权需求明确 |
| WebView2 | 已安装、缺失、下载失败、离线情况都有符合所选分发策略的结果 |
| 路径 | 中文用户名、含空格安装路径、不同入口启动均定位到同一数据库 |
| 图标与版本 | EXE、任务栏、开始菜单、桌面快捷方式和已安装应用显示一致；各处版本一致 |
| 首次使用 | 空数据目录完成来源识别、本地扫描和首次归档；未配置云端仍能本地使用 |
| 后台任务 | 关闭窗口后按约定运行；计划任务可创建、暂停、恢复，重启后可续作 |
| 重复运行 | 重复启动桌面程序及桌面与 CLI 同时运行时行为明确，无重复执行导致的数据破坏 |
| 覆盖安装 | 同结构资料库可重新打开，任务和凭据可用，旧进程退出与文件替换处理正确 |
| 卸载和重装 | 计划任务和快捷方式清理完整；默认保留的数据可重新打开，原附件和远端归档完整 |
| 故障反馈 | 初始化失败和安装失败可定位原因；发布模式下无控制台也能取得必要日志 |

建议实施顺序：数据目录与 CLI 分发 → 安装包闭环 → 品牌和版本统一 → 首次启动与卸载体验 → 干净 Windows 环境验收 → 对外分发。
