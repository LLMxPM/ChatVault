# 开发与构建

本文是 ChatVault 当前开发、检查、编译和 Windows x64 发布流程的唯一入口说明。

## 环境要求

本项目首期只支持 Windows x64 桌面构建。开发机和 GitHub Actions 均使用标准系统工具链，不依赖仓库外的固定路径。

| 依赖 | 要求 |
| --- | --- |
| Node.js | 22.x |
| pnpm | 10.30.3 |
| Rust | stable，MSVC host `x86_64-pc-windows-msvc` |
| Visual Studio | Build Tools，包含 C++ x64 工具 |
| Windows SDK | 安装并能提供 `kernel32.lib`、`OleAut32.lib`、`ucrt.lib` 和 `rc.exe` |
| SQLite | 仓库内 `libs/win_x64/sqlite3.lib`，包含 FTS5 |

Rust 工具链由根目录 `rust-toolchain.toml` 声明，pnpm 版本由根目录 `package.json` 的 `packageManager` 声明。不要依赖固定的开发机私有路径或第三方 mingw 工具链。

## 本地命令

所有命令从仓库根目录执行：

| 命令 | 用途 |
| --- | --- |
| `pnpm install --frozen-lockfile` | 按根锁文件安装前端依赖 |
| `pnpm dev:web` | 仅启动 Vite 前端开发服务 |
| `pnpm dev:desktop` | 启动完整 Tauri 桌面开发环境 |
| `pnpm check:frontend` | 前端 TypeScript/Vue 类型检查 |
| `pnpm build:frontend` | 构建前端生产资源 |
| `pnpm check:rust` | 校验 Windows 环境并检查 Rust workspace |
| `pnpm lint:rust` | 校验 Windows 环境并运行 Clippy |
| `pnpm test:rust` | 校验 Windows 环境并运行 Rust workspace 测试 |
| `pnpm test:installer` | 使用替身验证安装生命周期脚本，不触碰真实计划任务 |
| `pnpm build:desktop` | 构建前端并编译桌面端 Rust 二进制 |
| `pnpm release:windows` | 编译 CLI、打包 NSIS 安装器并生成 SHA256 |

Windows Rust 命令会先执行 `scripts/windows_environment.ps1`。该脚本会通过 `vswhere` 查找完整的 Visual Studio 安装，导入 x64 编译环境，并在编译前检查 Windows SDK 库、Rust host、Node、pnpm 和仓库 SQLite 静态库。

## 版本和产物

根目录 `package.json` 的 `version` 是发行版本真值。桌面包和 Cargo workspace 中的版本字段必须与其一致，由 `scripts/validate_versions.ps1` 校验。

Windows 发行产物位于 Cargo target 目录下的 `release/bundle/nsis/`，包括：

- NSIS 安装包 `*-setup.exe`
- 同名 SHA256 文件 `*.exe.sha256`

发行过程会先编译 `chatvault-cli.exe`，再将同版本 CLI 放入 Tauri 资源目录，最后构建安装器。未配置代码签名、自动更新、MSI、ARM64 或离线 WebView2 安装。

## GitHub Actions

CI 使用 `windows-2022` runner，并执行以下检查：

1. 安装 Node 22、pnpm 10.30.3 和 stable Rust。
2. 使用 `pnpm install --frozen-lockfile` 安装依赖。
3. 运行前端检查和构建。
4. 运行 Cargo 格式检查、Clippy、workspace 测试和桌面端编译。
5. 运行安装钩子隔离测试。

Pull Request 和主分支推送执行完整 CI。推送 `vX.Y.Z` tag 时，发布工作流会校验 tag 去掉 `v` 后等于根 `package.json` 版本，然后生成 NSIS 安装包、SHA256 文件并创建 GitHub Release。发布资产生成完成前不会创建公开 Release。

## 常见问题

### 找不到 `kernel32.lib` 或 `OleAut32.lib`

在 Visual Studio Installer 中修复 Build Tools，确认同时安装 C++ x64 工具和 Windows 10/11 SDK。不要只安装 `cl.exe`；桌面端和测试程序的链接阶段还需要 Windows SDK 库。

### 当前 pnpm 版本不正确

安装或启用 pnpm 10.30.3，然后重新执行：

```powershell
corepack enable
corepack prepare pnpm@10.30.3 --activate
```

### 前端依赖安装失败

确认从仓库根目录执行命令，并且只使用根目录 `pnpm-lock.yaml`。`apps/desktop/` 下不再维护单独锁文件。

### SQLite 链接失败

确认 `libs/win_x64/sqlite3.lib` 存在且为 Windows x64 静态库。`crates/index/build.rs` 会在 Windows 构建前直接报告缺失文件。

### 本地数据库或构建产物污染工作树

`target/`、`node_modules/`、`dist/`、`*.db` 和 `*.sqlite*` 都是本地产物，已由 `.gitignore` 忽略。Tauri 的 `src-tauri/gen/schemas/` 为当前提交的生成配置，修改 Tauri 配置后应检查差异并按需提交。
