# 开发与构建

本文是 ChatVault 当前开发、检查、编译和 Windows x64 发布流程的唯一入口说明。

## 环境要求

本项目首期只支持 Windows x64 桌面构建。开发机和 GitHub Actions 均使用标准系统工具链，不依赖仓库外的固定路径。

| 依赖 | 要求 |
| --- | --- |
| Node.js | 22.x |
| pnpm | 10.30.3 |
| Rust | stable，MSVC host `x86_64-pc-windows-msvc` |
| Visual Studio | Build Tools，包含 C++ x64 工具 |
| Windows SDK | 安装并能提供 `kernel32.lib`、`OleAut32.lib`、`ucrt.lib` 和 `rc.exe` |
| SQLite | 仓库内 `libs/win_x64/sqlite3.lib`，包含 FTS5 |

Rust 工具链由根目录 `rust-toolchain.toml` 声明，pnpm 版本由根目录 `package.json` 的 `packageManager` 声明。不要依赖固定的开发机私有路径或第三方 mingw 工具链。

## 本地命令

所有命令从仓库根目录执行：

| 命令 | 用途 |
| --- | --- |
| `pnpm install --frozen-lockfile` | 按根锁文件安装前端依赖 |
| `pnpm dev:web` | 仅启动 Vite 前端开发服务 |
| `pnpm dev:desktop` | 校验 Windows 环境，编译同目录 CLI，再启动完整 Tauri 桌面开发环境 |
| `pnpm check:frontend` | 前端 TypeScript/Vue 类型检查 |
| `pnpm build:frontend` | 构建前端生产资源 |
| `pnpm check:rust` | 校验 Windows 环境并检查 Rust workspace |
| `pnpm lint:rust` | 校验 Windows 环境并运行 Clippy |
| `pnpm test:rust` | 校验 Windows 环境并运行 Rust workspace 测试 |
| `pnpm test:installer` | 使用替身验证安装生命周期脚本，不触碰真实计划任务 |
| `pnpm build:desktop` | 构建前端，并编译 CLI 与桌面端 Rust 二进制 |
| `pnpm release:windows` | 编译 CLI、打包 NSIS 安装器并生成 SHA256 |

Windows Rust 命令（包括 `pnpm dev:desktop`）会先执行 `scripts/windows_environment.ps1`。该脚本会通过 `vswhere` 查找完整的 Visual Studio 安装，导入 x64 编译环境，并在编译前检查 Windows SDK 库、Rust host、Node、pnpm 和仓库 SQLite 静态库。工具链安装完整后，可直接从普通 PowerShell 运行这些命令，无需手动配置链接器路径。桌面开发命令通过 `scripts/build_windows.ps1 desktop-dev` 先编译 `chatvault-cli`，再启动 Tauri，让其 Vite/Cargo 子进程继承环境；附加参数会继续传给 `tauri dev`。计划任务只定位桌面程序同目录的 `chatvault-cli.exe`，因此开发与本地桌面构建都会把 CLI 编到同一 `target` 目录。

## 版本和产物

根目录 `package.json` 的 `version` 是发行版本真值。桌面包和 Cargo workspace 中的版本字段必须与其一致，由 `scripts/validate_versions.ps1` 校验。

Windows 发行产物位于 Cargo target 目录下的 `release/bundle/nsis/`，包括：

- NSIS 安装包 `*-setup.exe`
- 同名 SHA256 文件 `*.exe.sha256`

发行过程会先编译 `chatvault-cli.exe`，再将同版本 CLI 放入 Tauri 资源目录，最后构建安装器。未配置代码签名、自动更新、MSI、ARM64 或离线 WebView2 安装。

## GitHub Actions

CI 使用 `windows-2022` runner，并执行以下检查：

1. 安装 Node 22、pnpm 10.30.3 和 stable Rust。
2. 使用 `pnpm install --frozen-lockfile` 安装依赖。
3. 运行前端检查和构建。
4. 运行 Cargo 格式检查、Clippy、workspace 测试和桌面端编译。
5. 运行安装钩子隔离测试。

Pull Request 和主分支推送执行完整 CI。推送 `vX.Y.Z` tag 时，发布工作流会校验 tag 去掉 `v` 后等于根 `package.json` 版本，然后生成 NSIS 安装包、SHA256 文件并创建 GitHub Release。发布资产生成完成前不会创建公开 Release。

## 常见问题

### 找不到 `link.exe` 或提示 Visual Studio 安装不完整

MSVC Rust 工具链需要 Visual Studio 提供的链接器。`link.exe` 未进入当前终端环境，或 C++ 构建工具安装不完整，都会导致构建失败；仅安装 Rust 或 VS Code 不会补齐这些依赖。

1. 打开 Visual Studio Installer，完成或修复 Build Tools 安装；尚未安装时，从 [Microsoft C++ Build Tools 官网](https://visualstudio.microsoft.com/visual-cpp-build-tools/) 获取安装器。
2. 勾选“使用 C++ 的桌面开发”，确认包含 MSVC x64/x86 构建工具和 Windows 10/11 SDK。具体步骤见 [Tauri Windows 前置要求](https://v2.tauri.app/zh-cn/start/prerequisites/)。
3. 安装完成后重新打开 PowerShell，在仓库根目录运行 `pnpm dev:desktop`。

`dev:desktop` 会在启动 Vite 和 Cargo 前检查环境，安装状态不完整时直接停止。即使磁盘上已有 `link.exe`，也仍需要安装完整的 Windows SDK；只把链接器目录加入 `PATH` 无法补齐缺失的库。

### 加载 Visual Studio 环境时提示路径语法错误

若出现 `The filename, directory name, or volume label syntax is incorrect.`，应检查环境脚本是否把多套 Visual Studio 安装路径拼成了一个参数。根命令调用的是 `powershell.exe`（Windows PowerShell），即使外层终端使用 PowerShell 7 也一样。

`scripts/windows_environment.ps1` 先接收 `vswhere` 返回的 JSON 数组，再将安装记录逐项传入筛选管道，只选择安装完整且包含 C++ 工具的一条记录。不能在 `ConvertFrom-Json` 管道外再包一层 `@()`，否则 Windows PowerShell 会产生嵌套数组；例如同时存在完整的新安装和未完成的旧安装时，两条路径可能被一起传给 `vcvars64.bat` 调用。

### 找不到 `kernel32.lib` 或 `OleAut32.lib`

在 Visual Studio Installer 中修复 Build Tools，确认同时安装 C++ x64 工具和 Windows 10/11 SDK。不要只安装 `cl.exe`；桌面端和测试程序的链接阶段还需要 Windows SDK 库。

### 编译成功后启动失败，日志提示数据库缺少字段

先查看 `%LOCALAPPDATA%\com.chatvault.desktop\logs\desktop.log` 中的具体原因。数据库缺少 `source_type` 等当前必需字段时，说明仍在使用旧结构的开发索引。按开发阶段约束，关闭应用和使用该数据库的 CLI，先备份 `chatvault.db` 及同名 `-wal`、`-shm` 文件（若存在），再将它们移出数据目录，重新启动应用创建当前结构；需要的附件重新扫描入库。不添加历史迁移或自动删库逻辑，不移动原始附件和远端归档。

资料库初始化在进入桌面事件循环前完成，错误会同时输出到开发终端、日志和 Windows 提示框，避免被 Tauri 的 setup panic 掩盖。发生其他 panic 时仍保留默认终端输出，可用 `$env:RUST_BACKTRACE = '1'` 查看调用栈。退出时的 `Chrome_WidgetWin_0` 清理报错应结合此前日志判断，不能据此直接认定 WebView2 安装损坏。

### 当前 pnpm 版本不正确

安装或启用 pnpm 10.30.3，然后重新执行：

```powershell
corepack enable
corepack prepare pnpm@10.30.3 --activate
```

### 前端依赖安装失败

确认从仓库根目录执行命令，并且只使用根目录 `pnpm-lock.yaml`。`apps/desktop/` 下不再维护单独锁文件。

### SQLite 链接失败

确认 `libs/win_x64/sqlite3.lib` 存在且为 Windows x64 静态库。`crates/index/build.rs` 会在 Windows 构建前直接报告缺失文件。

### 本地数据库或构建产物污染工作树

`target/`、`node_modules/`、`dist/`、`*.db` 和 `*.sqlite*` 都是本地产物，已由 `.gitignore` 忽略。Tauri 的 `src-tauri/gen/schemas/` 为当前提交的生成配置，修改 Tauri 配置后应检查差异并按需提交。
